# gen-image

Generates a new image that matches the visual style of reference images. Prefers the deterministic `image_gen.py` CLI when an OpenAI key is available, and falls back to `codex exec` with the built-in `image_gen` tool (no `OPENAI_API_KEY` needed — uses codex's own auth). See "Why two paths" below for the reliability tradeoff.

## Args

```
tron:gen-image <sources> [subject description]
```

Where `<sources>` is one of:
- A folder path — auto-samples up to 5 representative images from it
- One or more image file paths (jpg, jpeg, png, webp)

And `subject description` is optional text describing what the new image should depict. If omitted, codex will generate a scene similar in subject matter to the references.

**Examples:**
```
tron:gen-image ~/Downloads/padma-pics/
tron:gen-image ~/Downloads/padma-pics/ a woman reading at a café
tron:gen-image ref1.jpg ref2.jpg ref3.jpg a dog in a park
```

## What to do

The mechanical pipeline — preflight codex auth, resolve refs, build the subject/medium
prompt, run `codex exec` with write access, and verify a real PNG landed — is baked into a
deterministic script so it can't drift (it used to fail late on a revoked token, run in a
read-only sandbox that couldn't write the output, and let style override the subject). **Run
the script.** Your only creative job is the subject text and the final visual self-verify.

**Step 1 — Run the bundled script.**

```bash
# Resolve the skill dir without relying on $CLAUDE_SKILL_DIR (not exported to this bash).
name=gen-image
SKILL_DIR="${CLAUDE_SKILL_DIR:-${CLAUDE_PLUGIN_ROOT:+$CLAUDE_PLUGIN_ROOT/skills/$name}}"
# fall back to the newest INSTALLED copy that actually contains scripts/gen-image.sh
# (skips a stale mirror that lacks it; newest version wins, marketplace breaks ties)
[ -e "$SKILL_DIR/scripts/gen-image.sh" ] || SKILL_DIR="$(for d in ~/.claude/plugins/cache/*/*/*/skills/$name ~/.claude/plugins/marketplaces/*/skills/$name; do [ -e "$d/scripts/gen-image.sh" ] && echo "$d"; done | sort -V | tail -1)"
[ -e "$SKILL_DIR/scripts/gen-image.sh" ] || { echo "tron:$name: can't find scripts/gen-image.sh — run /plugin update (or set CLAUDE_PLUGIN_ROOT)" >&2; exit 1; }

# gen-image.sh <sources-dir-or-file> [subject] [output.png]
OUT="$(bash "$SKILL_DIR/scripts/gen-image.sh" "<sources>" "<subject>" "<output.png>")"
```

The script samples up to 5 references, builds a prompt that makes the **subject mandatory**
and pins the **medium from the references** (so a B&W-photo ref set can't yield a sepia
illustration), generates the image, and verifies a real, fresh, non-trivial image landed at
the output path (exit `1` otherwise). It uses **two paths**, in order:

1. **Deterministic CLI (preferred).** If `OPENAI_API_KEY` is available (it's auto-sourced
   from `~/.env`), the script calls codex's bundled image CLI directly —
   `image_gen.py edit --image <refs> --prompt … --out <path>` (model `gpt-image-2`). This
   honors the output path exactly and never touches the flaky agent loop.
2. **Built-in tool fallback.** With no key, it preflights codex auth with a real round-trip
   (exit `3` + an A/B/C re-auth ask if the token is revoked — relay it verbatim and stop),
   then runs `codex exec -c features.image_generation=true` and copies out **only** an image
   generated by that run. If codex's built-in tool produces nothing (a known headless
   limitation — see Notes), the script exits `1` rather than ship a stale image.

> **For reliable, scriptable generation, set `OPENAI_API_KEY` in `~/.env`** and install the
> CLI deps once: `uv pip install openai pillow` (or `python3 -m pip install openai pillow`).
> Exit `4` means the `openai` package is missing.

**Step 2 — Self-verify the result (your judgment — the script can't do this).**

Read the generated image and check it actually depicts the requested subject in the right
medium. If it's clearly off (wrong subject, wrong medium), re-run the script **once** with a
tighter subject string, then hand to the user. Cap at one retry to bound cost.

```bash
open -a Preview "$OUT"   # macOS — avoids Photoshop hijacking PNGs
```

**Step 3 — Report the result.** Tell the user the output path and roughly what was generated.

## Notes

- **Why two paths:** generating through codex's agent loop (`codex exec` + built-in
  `image_gen`) is unreliable headless — the model narrates a tool call but the artifact often
  never lands in `$CODEX_HOME/generated_images/` (known issues openai/codex #28102, #19133,
  #23015). The `image_gen.py` CLI bypasses the loop and is deterministic, so it's preferred
  whenever a key is present.
- codex's ChatGPT session token can be revoked while `codex login status` still reports
  "logged in" — that's why the fallback relies on an actual round-trip, not the status string.
- The fallback passes `-c features.image_generation=true` so `codex exec` actually offers the
  tool, and copies out **only** an image newer than that run (never a stale one).
- Default size `1024x1024`, quality `high` (override via `GENIMG_SIZE` / `GENIMG_QUALITY`).
  `gpt-image-2` does not support transparent backgrounds. Typical time: 30–90 seconds.
- **Next step:** generated PNGs are large — before shipping one to the web or CDN, run
  `tron:optimize-images` to compress (and convert to WebP) it.
